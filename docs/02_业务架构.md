# OpenAI Images 适配微服务 — 业务架构

## 1. 业务愿景

> 让任意图像/多模态 AI 服务都能以 OpenAI 标准协议被消费，降低客户端集成成本，提升上游资源利用率。

### 2.1 客户端开发者（Consumer）

- **诉求**：使用熟悉的 OpenAI SDK 调用任意图像服务，无需学习各厂商专有 API
- **行为**：通过标准 `openai.Image.create()` / `openai.ChatCompletion.create()` 调用
- **感知**：完全无感知上游差异，如同调用原生 OpenAI 服务

### 2.2 平台运营者（Operator）

- **诉求**：统一管理多上游资源，监控用量、成本、质量，快速接入新上游
- **行为**：
  - 在 New API 配置渠道路由规则
  - 在 Adapter 编写/更新 Python 映射脚本
  - 在 Logfire 查看全链路监控大盘
- **感知**：脚本热更新秒级生效，错误快速归因到具体上游和脚本

### 2.3 上游接入方（Provider）

- **诉求**：将自有服务接入 OpenAI 生态，扩大客户群
- **行为**：提供 API 文档，由运营者编写映射脚本
- **感知**：无需修改自身服务，通过脚本适配即可接入

### 3.1 流量治理（New API 承载）

| 能力 | 业务价值 |
|------|---------|
| 统一鉴权 | 客户端使用单一 API Key，后端分发到不同上游 |
| 配额计费 | 按模型/按请求/按 Token 维度统计用量，支持限流和预警 |
| 智能路由 | 按延迟、可用性、成本自动选择最优上游渠道 |
| 模型映射 | 客户端使用语义化模型名（如 `dall-e-3-custom`），后端映射到上游真实 ID |

### 3.2 协议转换（Adapter 承载）

| 能力 | 业务价值 |
|------|---------|
| 请求转换 | 将 OpenAI 标准请求体映射为上游专有格式，屏蔽协议差异 |
| 响应转换 | 将上游响应重组为 OpenAI 标准格式，确保客户端兼容 |
| 工具编排 | 模拟 `image_generation` 等工具调用，实现多步骤业务逻辑 |
| 异步封装 | 将上游异步 Job 模式封装为同步接口，降低客户端复杂度 |
| 多模态处理 | 统一处理文本、图片 URL、Base64 的混合输入输出 |
| 图片编解码 | 统一处理 URL 下载、Base64 编码、格式转换、临时存储 |
| 认证签名 | 将统一鉴权转换为上流特有的 AK/SK 签名、临时 Token |
| 流式桥接 | 将上游非流式响应模拟为 SSE 流式输出，提升用户体验 |

### 3.3 上游接入

| 能力 | 业务价值 |
|------|---------|
| 同构代理 | OpenAI/Azure 等原生兼容上游零损耗透传 |
| 异构转换 | 国产模型、SD、MJ 等通过脚本灵活适配 |
| 异步轮询 | 支持 Job 模式上游的自动状态轮询和结果获取 |
| 状态同步 | Responses API 的 `previous_response_id` 状态链维护 |

## 4. 核心业务流

### 4.1 异构文生图（/v1/images）

```
┌─────────┐     ┌──────────┐     ┌──────────┐     ┌──────────┐     ┌─────────┐
│ 客户端   │────►│ New API  │────►│  Adapter  │────►│  脚本引擎  │────►│ 上游服务 │
│         │     │  (路由)   │     │ (Gateway) │     │ (Python)  │     │         │
└─────────┘     └──────────┘     └──────────┘     └──────────┘     └─────────┘
     │               │               │               │               │
     │ ① 请求生图     │               │               │               │
     │ model=custom   │               │               │               │
     │ prompt="猫"   │               │               │               │
     │──────────────►│               │               │               │
     │               │ ② 鉴权通过     │               │               │
     │               │ 路由到Adapter  │               │               │
     │               │──────────────►│               │               │
     │               │               │ ③ 解析model    │               │
     │               │               │ 加载upstream_a │               │
     │               │               │ /images.py     │               │
     │               │               │──────────────►│               │
     │               │               │               │ ④ 字段映射     │
     │               │               │               │ prompt→desc    │
     │               │               │               │ size→resolution│
     │               │               │               │ quality→steps  │
     │               │               │◄──────────────│               │
     │               │               │ ⑤ 发送请求     │               │
     │               │               │──────────────►│──────────────►│
     │               │               │               │               │ ⑥ 生成图片
     │               │               │◄──────────────│◄──────────────│
     │               │               │ ⑦ 接收响应     │               │
     │               │               │ (URL/二进制)   │               │
     │               │               │──────────────►│               │
     │               │               │               │ ⑧ 响应转换     │
     │               │               │               │ URL→Base64     │
     │               │               │               │ 组装OpenAI格式 │
     │               │               │◄──────────────│               │
     │               │◄──────────────│               │               │
     │◄──────────────│               │               │               │
     │ ⑨ 标准响应     │               │               │               │
     │ data[0].b64   │               │               │               │
     │               │               │               │               │
```

**业务规则**：
- 若上游返回 Job ID（异步），Adapter 启动轮询，超时 120s 后返回错误
- 若 `n > 1` 且上游不支持批量，脚本内部串行/并行调用 `n` 次后聚合
- 图片下载和 Base64 编码由 `ctx` 基础设施统一处理，脚本只关注逻辑映射

### 4.2 Vision 理解（/v1/chat）

```
客户端 ──► 发送 messages（含 image_url）
    │
    ▼
Adapter ──► 脚本遍历 messages
    │
    ├──► 提取 text ──► 拼接为上游 prompt
    │
    ├──► 提取 image_url ──► ctx.image_bytes/b64() ──► 三态归一为 bytes
    │
    └──► 按上游要求编码 ──► base64 / multipart / 上传临时存储后传 URL
    │
    ▼
发送重组后的请求到上游
    │
    ▼
接收上游文本响应 ──► 脚本透传/微调 ──► 返回标准 ChatCompletion 格式
```

### 4.3 Agent 工具模拟（/v1/responses）

```
客户端 ──► 请求 /v1/responses
    input: "画一只橘猫在沙发上"
    tools: [{"type": "image_generation"}]
    │
    ▼
Adapter ──► 脚本判断意图（关键词/规则/轻量模型）
    │
    ├──► 调上游文本模型 ──► 生成优化英文 prompt
    │       "A ginger cat sleeping on a cozy sofa, soft lighting, realistic style"
    │
    ├──► 调上游文生图模型 ──► 获取图片结果（URL/二进制）
    │
    └──► 组装 Responses 标准 output 数组
            [
              {type: "message", content: "已为您生成图片"},
              {type: "image_generation_call", result: "data:image/png;base64,..."}
            ]
```

**业务规则**：
- 工具模拟对客户端完全透明，客户端感知为原生 OpenAI Responses 能力
- 中间结果（优化 prompt、生图参数）可缓存于 Redis，避免重复调用
- 若上游文本模型失败，返回友好错误，不暴露内部编排细节

## 5. 业务对象模型

### 5.1 核心实体

| 实体 | 属性 | 说明 |
|------|------|------|
| **Upstream** | name, base_url, timeout, auth_type, models[] | 上游服务注册信息 |
| **Script** | upstream, endpoint, path, version, last_modified | 映射脚本元数据 |
| **Request** | request_id, endpoint, model, upstream, duration_ms | 请求追踪记录 |
| **Job** | job_id, upstream, status, created_at, result | 异步任务状态 |
| **Image** | url, b64_data, format, size_bytes, temp_key | 图片资源（临时存储） |

### 5.2 状态机（异步 Job）

```
[PENDING] ──► [RUNNING] ──► [SUCCEEDED] ──► 返回结果给客户端
                │              │
                ▼              ▼
            [FAILED]      [CANCELLED]
                │              │
                └──────────────┘
                    返回错误
```

**状态转换触发**：
- `PENDING → RUNNING`：Adapter 向上游提交请求成功
- `RUNNING → SUCCEEDED`：轮询获取到最终结果
- `RUNNING → FAILED`：上游返回错误，或轮询超时（>120s）
- `RUNNING → CANCELLED`：客户端主动取消（扩展协议）

## 6. 业务规则清单

| 规则编号 | 规则描述 | 优先级 |
|----------|----------|--------|
| BR-001 | 同构上游（OpenAI/Azure）请求体透传，不做字段转换。**注意：`X-Script-Ref` 是必填的**——没有无脚本的透传旁路，同构场景由恒等脚本（原样返回 payload）承担，以免出现绕过沙箱与校验的第二条执行路径 | P0 |
| BR-002 | 异构上游必须通过脚本映射，禁止硬编码转换逻辑 | P0 |
| BR-003 | 脚本相位（`transform` 的 `auth`/`request`/`response`/`poll_*`）单次执行超时 30s（`script_timeout`），超时返回 **504** `code=script_timeout` | P0 |
| BR-004 | 异步上游轮询超时 120s（`poll_timeout_default`），超时返回 **504** `code=poll_timeout`；另有 `poll_max_attempts` 次数上限与级联总预算两道闸 | P0 |
| BR-005 | 图片临时存储 TTL 1 小时（`temp_image_ttl`），过期自动清理 | P1 |
| BR-006 | **未实现，且暂不实现**：无「prompt + model + size → 结果」的生成结果缓存。适配器不解析 model、不理解厂商语义，无法安全判定两次请求等价（seed / 随机性 / 渠道差异都会影响产物）。现存的 `img_cache_ttl`(300s) 只缓存**按 URL 下载的素材图**，与生成结果无关，勿混淆 | — |
| BR-007 | 客户端要求 `b64_json` 时，若上游返回 URL，必须下载后编码 | P0 |
| BR-008 | 客户端要求 `url` 时，若上游返回二进制，必须上传 MinIO 后返回预签名 URL；**MinIO 未配置时降级为 data URI**，不报错 | P0 |
| BR-009 | 脚本异常不得暴露堆栈给客户端，返回标准化错误消息（仅回传异常类型名，见 §3.3） | P0 |
| BR-010 | 所有响应必须回传 `X-Request-Id`；取 `request.state.request_id`，缺失则由适配器生成 uuid4 | P0 |

### 6.1 级联规则（v1.1 新增）

| 规则编号 | 规则描述 | 优先级 |
|----------|----------|--------|
| BR-011 | 级联请求持有统一总预算（默认 300s，上限 600s），各级超时从**剩余预算**中取，任一单级不得超出总预算 | P0 |
| BR-012 | 图像处理能力只经 `ctx.image` 门面暴露，脚本不得 import Pillow；单图解码上限 50 MP、输出上限 20 MB，超限拒绝 | P0 |
| BR-013 | 后处理级（超分、格式转换等）失败时，若 `ctx.stage` 已有可用产物则按 `STAGE_FALLBACK` 降级返回并标记 `degraded` + `degraded_reason`，不整单失败 | P0 |
| BR-014 | 级联只在单一上游内串联多级：上游 base_url 与凭证由 channel 头单值提供，跨上游编排不在本项目范围内 | P0 |
| BR-015 | 级联的实际上游调用量按 `n × len(STAGES)` 计，限流按实际调用次数计费；级内批量并发不超过 `concurrency`（默认 3） | P1 |
| BR-016 | 级间中间产物与最终产物同样受 BR-005 的 TTL 约束，请求结束后不得长期驻留 | P1 |
